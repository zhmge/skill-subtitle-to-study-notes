# 笔记格式

写笔记前先读这份。它规定了骨架，以及让成品"能学"而不是"能读"的几条规则。

## 目标读者

**读者没看过这个视频。** 这条决定了所有取舍：笔记不能是"讲者说过的话的整理稿"，它必须是一份**能独立学懂**的材料。三个后果：

- 读者不知道"屏幕上那个图"长什么样 → 需要重建（见下）。
- 读者不知道哪个概念重要 → 需要**明确的重点信号**。
- 读者不知道先看什么 → 需要**学习地图**。

同时，读者**随时可能去回看视频**（尤其当笔记里的重建不如原图时）。所以每节都要能一键跳回原片。

## 总骨架

```markdown
# <视频标题> 学习笔记
> 来源：<字幕文件名> ｜ 时长 <HH:MM:SS> ｜ 由字幕整理，不含原视频画面

## 学习地图
## 一、<板块名>
### 1.1 <概念名> [00:01:00](<跳转链接>)
### 1.2 <概念名> [00:02:01](<跳转链接>)
## 二、<板块名>
### 2.1 <概念名> [00:03:19](<跳转链接>)
---
## 术语表
## 结构图
```

只有两级内容标题：`##` 是板块，`###` 是概念。板块编号用 `一、二、三`，概念编号用 `1.1 / 1.2 / 2.1`。**概念编号在整个文件里连续**，方便引用"第 3.2 节"。

## 顺序：不搬家，只分板块

讲者讲概念的**先后顺序不变**——`###` 的顺序必须与字幕段落的顺序一致，时间戳因此**严格递增**（这是可自动检查的硬指标）。

允许的整理只有两件：

1. **分板块**——把连续的概念划进同一个 `##` 板块。
2. **板块命名**——给板块起一个概括性的名字。

不允许：把后面的概念提到前面、把讲者分开讲的内容合并、按自己的分类法重排。

> 这条规则不是洁癖。顺序一乱，读者回看视频就找不到位置，笔记与视频的对应关系就断了。

### 板块怎么划

- **2–5 个板块**（20 分钟的讲座）。太细等于没分；太粗等于没分。
- **每个板块至少 2 个概念。** 只有一个概念时不要单独成板块，并进相邻板块（例：把「生成树」并进「连通性与生成树」）。
- **切分点必须落在讲者自己的转换处**——换主题、给出新定义、说「接下来/下面/再看」。不要按篇幅均分。
- 板块名要能概括，不要用「第一部分」「其他」这种空名。

样本（《图 - 定义, 术语, 性质》，14 个概念）的一种划法：

| 板块 | 概念 |
|---|---|
| 一、图的基本记法 | 从线性表、树到图 / 顶点、边与 G=(V,E) / 无向图与有向图 |
| 二、术语总览与图的分类 | 九个术语总览 / 完全图 / 稀疏图与稠密图 / 权与网 |
| 三、顶点之间的关系 | 邻接 / 度、入度与出度 |
| 四、路径与子图 | 路径、简单路径、回路 / 子图 |
| 五、连通性与生成树 | 连通、连通图与连通分量 / 强连通与强连通分量 / 生成树 |

## 每个概念写什么

```markdown
### 3.2 度、入度与出度 [00:08:16](<跳转链接>)

> **本节结论**：无向图的度 = 与顶点相连的边数；有向图把它拆成入度和出度，且 总度 = 边数 × 2。

<正文——按讲者原意展开，压缩非重点，见下>

> **板书重建（非原视频画面）**：<讲者此时在图示什么>

**关键点**
- <只放讲者强调过的，或定义/判据>
- ……
```

三块的分工：

**本节结论**（必写，除非确实没有可归并的结论）——一句话，读完能带走的东西。**它必须来自下面两类来源之一**，不能是自己概括的感想。这一行是整节的"承重墙"，读者扫一遍结论卡就等于扫了一遍全篇。

可选在正文第一句补一句**它为什么在这里 / 与前文什么关系**（例：「上一节把顶点和边分开了，这一节开始给它们各自定量的属性」）。**有则写，没有就跳过——硬凑一句比不写更糟。** 判断标准：这句话能不能帮读者接得上前文？不能就别写。

**正文**——见「压缩」。

**关键点**——2–5 条，每条一句。**只放两类内容**（见「重点判定」）。若本节一条都挑不出来，**整块省略**，不要留一个空标题，也不要为了凑数把反例、数量关系塞进来。

## 重点判定：只有两个合法来源

"重点突出"不是靠把关键句加粗，而是靠**舍得把非重点降级**。所以先定死什么算重点——**只有两类**：

1. **讲者的强调信号**——他说「注意」「很重要」「必须」「关键」「总结一下」的地方。
2. **定义与判据**——术语的定义、成立条件、判定方法。

**其他一切都不进结论卡与关键点**，包括：反例、数量关系式、举例过程、教材补充。这些**照常写在正文里**，只是不加重点标记——它们在正文中的位置和篇幅不受影响，只是不占据视觉焦点。

数量关系有两条边界，必须分清：

1. **定义里内含的数字照写。**「有向完全图共 N(N − 1) 条边」是术语的**定义**，属于来源 2，可以进关键点。
2. **纯量关系默认不进**——除非讲者自己用强调语把它结成了结论（例：「OK 那咱们来总结一下，不管有向无向，总的度数都等于边数的两倍」）。这时它落进来源 1（讲者的强调信号），**强调优先**，可以进关键点。只是推演过程中顺带算出来、没有任何强调记号的量关系，留在正文。

解析脚本会输出四块证据，务必分清用途：

| 证据块 | 内容 | 用途 |
|---|---|---|
| Speaker stress signals | 讲者的强调用语 | **进重点** |
| Definition sentences | 定义/命名句式 | **进重点** |
| Bound / criterion statements | 「至少/最多/不超过」 | **只在正文**，不进重点 |
| Speaker waved-through passages | 讲者说「了解一下就可以」 | 只用于学习地图的阅读顺序标记 |

证据块是**线索，不是判决**。有标记不等于重要（`就是` 几乎每段都有）；没标记不等于不重要（讲者可能用平淡语气给了一个关键判据）。最终由内容决定。

## 压缩非重点

**压缩的是表达，不是内容。** 可以合并、省略的东西：

- 口语填充（「哈」「哎」「咱们」「对吧」「OK」）、重复啰嗦、说错又改口的过程。
- 举例的**推演过程**——可以压成一句。
- 讲者绕远路又绕回来的话。

**不能省的**：

- **例子本身**。推演过程可以压，但"从 A 到 C 再到 B 最后到 D"这个例子必须留下。
- **因果链**（「因为…所以…」「否则」「之所以」）。
- **对比**（「左边…右边…」「与之相反」「反过来」）。
- **反例**。反例虽不算重点，但它是理解边界的关键，必须完整保留在正文。

压到一句的例子：讲者用 40 秒反复举例说明「一条边给两个端点各贡献一个度」→ 正文写成一句：「一条边会给它的两个端点各贡献一个度，所以 N 条边贡献 2N 个度——总度数一定等于边数的两倍。」

## 补视频之外的背景：唯一允许的越界

讲者会默认听众已经知道某些事（「这跟我们讲树的时候一样」）。读者没看过，会卡住。

允许补**最小必要铺垫**，且必须遵守：

- **格式**：`[补充] <一句话>`，紧跟在被解释的内容之后。
- **限度**：只为让讲者的话被读懂。不扩写、不举例延伸、不引教材定义。
- **数量**：一篇 20 分钟的笔记通常 0–5 处。超过 8 处说明你在写教材，不是在整理这个视频。
- **不得与讲者冲突**。讲者说错的地方**不改**——那是保真，不是错误。

正文其余部分仍然**禁止引入视频外的知识**。术语纠错（`references/asr-correction.md`）是另一件被许可的事，与 `[补充]` 分开。

## 板书重建

字幕里没有图像，但讲者一直在指：「屏幕上这个图」「咱们对比左边和右边」。忽略会让笔记看起来是坏的；凭空编出图更糟。

- **只用讲话支持得起的内容重建。** 讲者的词足够还原对比、列表、结构，就重建；不够，就写 `原图未出现在字幕中，需回看视频 [00:07:12](<跳转链接>)`。
- **前缀固定** `> **板书重建（非原视频画面）**：`。绝不能让人误以为是截图。
- **形式按内容选**：对比 / 枚举 / 属性 → 表格；结构 / 层次 / 流程 / 关系 → Mermaid；公式或记号 → 行内数学或代码span。
- Mermaid 用通用渲染器都认的标准语法，避免异形节点、自定义主题、`click`。
- **放在讲者画它的地方**，不要集中到文末。文末的「结构图」是全局地图，不是重建的收容所。

## 学习地图

放在正文之前，回答"这趟车往哪开"。三件：

1. **一段话**：这份笔记覆盖什么（几个概念、几个板块）、讲者走的什么路线。只讲路线，不讲额外知识。
2. **一张 Mermaid 路线图**：按**推进顺序**画板块，让人一眼看出先后与依赖。只画板块级，不要把每个概念都塞进去——各概念的细节在下文。
3. **推荐阅读顺序**：按板块给一条路径，并标出——
   - 哪些板块是后面内容的前提（必须先看）；
   - 哪些是讲者自己说「了解一下就可以」「后面会讲」的（可略读）——**只有脚本的 waved-through 证据块里有的，才可以这样标**。

**不要在这一节里塞结论、定义或补充知识**；它是导航，不是摘要。

**与末尾「结构图」的分工**（两处都画 Mermaid，但不能画成同一张）：

| | 学习地图的图 | 末尾的结构图 |
|---|---|---|
| 回答的问题 | 先看什么、后看什么 | 这些概念怎么归类 |
| 粒度 | 板块级（5 个左右节点） | 概念级（含全部讲过的术语） |
| 拓扑 | 一条链 / 有向流程 | 分层的树 |
| 依据 | 讲者推进的顺序 | 讲者自己给出的分类依据（如「按边有无方向」） |

## 跳转链接

平台识别得出来时（脚本会从文件名里找 BV/av 号），**时间戳本身做成链接**：

```markdown
### 3.2 度、入度与出度 [00:08:16](https://www.bilibili.com/video/BV12QASzrErF?t=496.0)
```

- `t` 的参数是**秒**。取该节**标题上显示的 HH:MM:SS 换算成的整秒**（截断到秒，不四舍五入），这样 `t=` 能被标题直接验算：`[00:08:16]` ↔ `t=496.0`。宁愿跳早 1 秒，也不要跳晚。
- **发出任何链接前，先确认这个 BV/av 号真的是这个视频的。** 脚本只是从文件名里正则匹配到的，可能匹配到别的视频号——一错，全篇时间戳都指向别处。
- 识别不出视频号时，退回纯文本 `[00:08:16]`，不要编。

## 结尾两块

**术语表**——讲者当作术语介绍的每一个词，按出现顺序。释义要反映**讲者怎么定义的**，不是教科书释义。英文列给标准英文术语；讲者自己给出英文的（「V 就是 vertex 的缩写」），保留他的形式并在「词源 / 出处」注明。讲者没提词源就留空，不要自己补。

**结构图**——一张 Mermaid，画这份笔记里概念之间的关系。它只能包含讲者讲过的概念。整篇没有关系结构（就是一串互不相干的事实）时，省略这一节，不要硬画。

## 不确定的地方要看得见

转写含糊或讲者没说清时，明说，或行内标注，例如
``[疑为转写误差：<原文>，建议核对 00:12:34]``。不要抹平。

## 不要加

- 公式 / 性质汇总表
- 自测题、练习题
- 延伸阅读、扩展知识
- 自己的评论章节
- 全篇性的「核心结论速览」「易错点汇总」（易错内容留在各节正文里）

用户明确排除以上内容。要的话单独产出，不进默认笔记。
